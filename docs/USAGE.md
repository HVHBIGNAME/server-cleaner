# Справка Server Cleaner

Все пользовательские действия выполняются одной программой — `server-cleaner`.
Полный список параметров: `server-cleaner --help` или `server-cleaner --lang en --help`.

## Установка и обновление

```sh
# Установить из checkout без доступа к сети
sh server-cleaner.sh --install --from "$PWD"

# Установить в свой каталог
sh server-cleaner.sh --install --from "$PWD" --prefix "$HOME/tools"

# Системная установка
sudo sh server-cleaner.sh --install --system

# Установить и сразу настроить ежедневную очистку
sh server-cleaner.sh --install --autostart daily --at 04:00 --only packages,journal --keep-days 30

# Обновить уже установленную программу
server-cleaner --update
```

`--install` устанавливает только `PREFIX/bin/server-cleaner`. Обновление определяет префикс
по пути текущей команды. `--prefix` позволяет выбрать его явно. `--system` выбирает
`/usr/local` и требует root. Отдельные команды удаления и инвентаризации из ранней v2
удаляются при обновлении, если принадлежат Server Cleaner.

Проверяются SHA-256, синтаксис shell и маркер программы; замена подготовленного файла
выполняется переименованием. При ошибке скачивания существующая программа сохраняется.
`--from DIR` использует локальные `server-cleaner.sh` и `SHA256SUMS`. Для фиксированной версии
скачайте `server-cleaner.sh` из нужного коммита и передайте тот же полный SHA через `--ref`.

Установка сама по себе не запускает очистку. Для выполнения сразу добавьте `--apply`
и, если нужна автоматическая работа без вопросов, `--yes`.

## Действия очистки

| `--only` | Действие |
| :-- | :-- |
| `packages` | Штатная очистка кеша пакетного менеджера |
| `journal` | Архивные журналы systemd старше `--keep-days` |
| `temp` | `/tmp` и `/var/tmp` по возрастным правилам systemd-tmpfiles |
| `logs` | Плановая ротация через logrotate / newsyslog по конфигурации ОС |
| `coredumps` | Дампы по правилам systemd-tmpfiles |
| `docker` | Неиспользуемый кеш сборки локального Docker старше `--keep-days` |
| `history` | Собственные сохранённые файлы Bash, Zsh, Fish, Vim, Less, Nano |

По умолчанию: `packages,journal,temp,logs,coredumps`. `docker` и `history` включаются
явно. Пример выбора: `--only packages,journal`. `--list` показывает доступность всех действий.

`--keep-days` принимает **1..3650**, по умолчанию **14**. Применяется к journal,
Docker и Homebrew. В остальных случаях используются правила самой системы.
История открытого shell остаётся в памяти и может быть записана снова при выходе.
Запускайте программу, а не подключайте её через `source`.

## Автозапуск

```sh
server-cleaner --autostart daily --at 04:00 --only packages,journal --keep-days 30
server-cleaner --autostart weekly --at 02:30 --only packages
server-cleaner --autostart boot --only temp,coredumps
server-cleaner --autostart status
server-cleaner --autostart off
```

- `daily`: ежедневно; `weekly`: по воскресеньям. Время по умолчанию **03:17**, часовой пояс сервера.
- `boot`: запись cron `@reboot` — при запуске демона cron, обычно при загрузке системы.
- `--at HH:MM`: только для `daily` / `weekly`.
- В задании сохраняются `--only`, `--keep-days`, `--lang`, `--quiet`, HOME и каталог состояния.
- Можно настроить расписание сразу при `--install` или изменить после установки тем же флагом.
- Нужен установленный и работающий cron. Программа не устанавливает и не запускает демоны.
- Работает с crontab текущей учётной записи. Для системных действий нужен root;
  обычный пользователь может настроить, например, `--only history`.
- Изменяется только собственный отмеченный блок. Повторное включение обновляет его,
  `off` удаляет. Вывод задания доступен через настроенную доставку cron.

`--autostart` настраивает последующие запуски. Чтобы также запустить очистку сейчас,
добавьте `--apply --yes`. Параметры `off` и `status` не совмещаются с очисткой.

## Вывод и автоматизация

- `--dry-run`: предварительный просмотр очистки; это поведение по умолчанию.
- `--apply`: выполнить после подтверждения; `--yes` подтверждает без вопроса.
- `--json`: JSON-отчёт очистки в stdout, вывод нативных команд в stderr.
- `--quiet`: убрать обычный интерфейс, сохранив ошибки; `--silent` — совместимый синоним.
- `--no-color` / `NO_COLOR`: отключить цвет.
- `--lang ru|en`: язык интерфейса.

`--json`, `--list` и `--dry-run` относятся к очистке и не сочетаются с установкой,
удалением, инвентаризацией или настройкой автозапуска. Конфликтующие флаги приводят к ошибке.

В JSON находятся `tasks[]` с командами и статусами, `summary` и снимки диска `/` в KiB.
Изменение доступного места включает активность других процессов. Отдельные `/var` и
`$HOME` могут не влиять на этот показатель. Неизвестные измерения и результат «после»
для предварительного просмотра — `null`.

## Совместимость

Пакетные менеджеры: APT, DNF5/DNF/microdnf/YUM, Zypper, paccache/Pacman, APK, XBPS,
eclean-pkg, eopkg, Homebrew и FreeBSD pkg. Отсутствующие возможности отображаются как `skipped`.

CI: Ubuntu 24.04 x86-64/ARM64, Debian 12/13, Alpine 3.22, Fedora 43, Rocky 9,
UBI 9 minimal, Arch, openSUSE Leap 16, macOS и FreeBSD 14.3.
Контейнеры проверяют реальную очистку кеша пакетов, но не все службы загруженной ОС.
Void/Gentoo/Solus имеют тесты адаптеров. OpenBSD/NetBSD — ограниченная поддержка доступных
утилит без native CI. Windows — через Linux в WSL. Специальных адаптеров Nix/Guix нет.

## Удаление и переход с v1

```sh
server-cleaner --uninstall --yes
sh server-cleaner.sh --uninstall --prefix "$HOME/tools" --yes  # Если команда уже удалена
sh server-cleaner.sh --install --migrate-legacy --yes           # Переход с v1
```

Удаление отключает свой автозапуск и удаляет программу; очистка системы не запускается.
Повторное удаление допустимо. Миграция v1 удаляет распознанный `.cache/system/.sysupdate`
и точную исходную строку cron текущего пользователя. Изменённые вручную старые задания
проверьте отдельно. `--agents` выполняет только инвентаризацию известных облачных пакетов.

## Ошибки и блокировки

Коды: `0` — успешно, возможны пропуски; `1` — ошибка действия; `2` — неверные аргументы
или нет подтверждения; `3` — неподдерживаемая ОС / нет обязательной утилиты;
`75` — блокировка; `130` / `143` — прерывание. Ошибки до формирования плана могут не иметь JSON.

Блокировка: `${XDG_STATE_HOME:-$HOME/.local/state}/server-cleaner/lock`.
После SIGKILL или отключения питания проверьте PID в `lock/pid` и отсутствие активного
процесса перед удалением устаревшей блокировки. Используйте один каталог состояния на учётную запись.
